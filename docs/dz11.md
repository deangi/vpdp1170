# DZ11 Unibus serial multiplexer

vpdp1170 presents a DEC DZ11-compatible 8-line Unibus mux to the guest and
bridges **line 0** to a second Telnet listener. The console KL11 remains on
the primary Telnet port.

## Guest programming

| Item | Value |
|------|-------|
| CSR base | `0160100` |
| Registers | CSR, RBUF/LPR, TCR, MSR/TDR (same layout as SIMH / EK-DZ11) |
| RX vector | `0310` |
| TX vector | `0314` |
| BR level | 5 |
| Lines | 8 (line 0 = Telnet; 1–7 disconnected stubs) |
| RX silo | 64 characters on the active (Telnet) line only |

LPR bit `RCVE` (`10000`) must be set for a line before received data sets
CSR `RDONE` and raises the RX interrupt (SIMH-compatible).

## Host configuration (`/wificonfig.ini`)

```ini
[telnet]
enabled = true
port    = 23

[dz11]
enabled = true
port    = 2323
```

- Console Telnet (management shell + KL11) uses `[telnet]`.
- DZ Telnet is raw 8-bit with minimal IAC negotiation — **no** management shell.
- Change `port` in `[dz11]` to any free TCP port; do not hard-code it in firmware.
- Set `enabled = false` to leave the Unibus DZ11 off at runtime (no second
  Telnet listener, no guest mux attach).

## Performance

With DZ11 compiled in and enabled, status-bar MIPS during a busy guest workload
(e.g. 2.11BSD memory-size probe) drops about **10–15%** versus a build with
`VPDP_ENABLE_DZ11` set to `0` in `platform.h` (measured ~0.21 vs ~0.25 MIPS on
that path). Cost is mainly extra flash/I-cache pressure plus deferred-device /
second-Telnet host work — not guest disk I/O.

For maximum IPS when multi-user serial is unused, either:

- set `[dz11] enabled = false` in `/wificonfig.ini`, or
- rebuild with `#define VPDP_ENABLE_DZ11 0` in `platform.h` (strips the device
  and `telnet_dz` from the binary; runtime `[dz11]` is ignored).

Default is compiled in (`VPDP_ENABLE_DZ11 1`) and `[dz11] enabled = true`.

## Using two sessions

1. Connect Putty/Telnet to the board on the console port (default 23) for the
   PDP-11 console / OS bootstrap.
2. Connect a second client to the DZ port (default 2323 from the INI template)
   for DZ11 line 0 traffic once the guest enables that line.

Only one client is accepted per listener.

## SIMH reference gaps (intentionally deferred)

Compared to SIMH `pdp11_dz.c`, this port:

- Enforces a **64-byte RX silo on line 0 only** (inactive lines have no FIFO).
- Implements LPR **RCVE** gating; baud/char-size from LPR are accepted but not
  applied to the Telnet socket.
- Does not yet raise silo-alarm (**SA/SAE**) interrupts; RDONE + RIE is enough
  for typical OS bring-up.
- Modem RI/CD track Telnet connect/disconnect; no modem IRQ (matches hardware).

Use SIMH as the oracle if a guest driver misbehaves on CSR bit patterns.

**RSTS notes:**
- CSR `CLR` must clear pending RX/TX interrupts, not raise one.
- Do not assert `TRDY` out of reset or synthesize it on CSR read from TCR
  enables — that primed `Unexpected trap through the vector at 000314`.
- `TRDY` requires MSE + XMTE + a connected Telnet client on that line.
